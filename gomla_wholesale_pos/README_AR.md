# Gomla Wholesale POS — Odoo 19 Community

الإصدار: `19.0.1.0.0`  
الحالة: Vertical Slice قابل للتثبيت والاختبار

## ما الذي ينفذه هذا الإصدار؟

هذا الموديول يمدد واجهة **Point of Sale القياسية في Odoo 19** ولا يستبدلها. يحتفظ بذلك بالتزامن المحلي المؤقت، الجلسات، طرق الدفع، المخزون، العملاء، الصلاحيات وطباعة إيصال Odoo.

المزايا المنفذة:

- إنشاء شحنات الموردين وربط كل صنف بكمية مستلمة.
- تحميل الشحنات النشطة داخل الـPOS باستخدام `pos.load.mixin` الرسمي في Odoo 19.
- زر عربي **بيانات الشحنة** داخل شاشة البيع.
- إلزام الصنف المخزني بشحنة عند اعتماد البيع، حسب إعداد نقطة البيع.
- إدخال الوزن/الكمية، عدد العبوات، البياعة، وعدد البرانيك ورهنها.
- إضافة البياعة والرهن كسطري خدمة منفصلين؛ لذلك يدخلان في المبلغ المطلوب من العميل ولا يدخلان في إجمالي مبيعات المورد.
- قفل صف الشحنة في PostgreSQL قبل التحقق من الكمية لمنع البيع المتزامن فوق المتاح.
- تحويل الشحنة تلقائيًا إلى `Pending Settlement` عند نفادها مع تسجيل وقت النفاد.
- تصفية الشحنة بمعادلة:

  `Supplier Net = Gross Sales - Supplier Commission - Freight - Aqlamiya`

- حفظ Snapshot نهائي غير قابل للتعديل وإنشاء حركة مستقلة في سجل المورد.
- Design Tokens أولية في SCSS للون الأساسي، نصف القطر والمسافات.
- اختبارات للمعادلة الرسمية `85,430 → 78,200`، واستبعاد البياعة، وعدم قابلية تعديل التصفية المعتمدة.

## التثبيت

1. انسخ مجلد `gomla_wholesale_pos` إلى مسار `custom_addons`.
2. أعد تشغيل خدمة Odoo 19.
3. فعّل Developer Mode ثم حدّث Apps List.
4. ثبّت **Gomla Wholesale Fruit Market POS**.
5. امنح الموظفين صلاحية `Gomla User` والمدير صلاحية `Gomla Manager`.

## الإعداد الأول

1. ينشئ الموديول تلقائيًا منتجي خدمة باسم **البياعة** و**رهن البرانيك**.
2. افتح إعداد نقطة البيع ثم تبويب **Gomla Wholesale**.
3. فعّل الموديول وتأكد من اختيار منتجي البياعة والرهن الافتراضيين.
4. من جهات الاتصال، فعّل **Wholesale Produce Supplier** للمورد وحدد نسبة العمولة.
5. من تطبيق **Gomla POS** أنشئ شحنة وأضف الأصناف والكميات.
6. افتح جلسة POS جديدة أو أعد تحميلها كي تصل بيانات الشحنة إلى التخزين المحلي.

## دورة البيع

1. أضف الصنف بالطريقة القياسية.
2. حدد السطر واضغط **بيانات الشحنة**.
3. اختر الشحنة ثم أدخل الوزن/الكمية والعبوات والبياعة والبرانيك.
4. يكّون الموديول سطور البياعة والرهن آليًا عند الحاجة.
5. أكمل الدفع والطباعة من Odoo بصورة طبيعية.

## التحقق والاختبارات

تشغيل اختبارات الموديول على قاعدة اختبار:

```bash
./odoo-bin -d gomla_test \
  --addons-path=addons,custom_addons \
  -i gomla_wholesale_pos \
  --test-enable \
  --test-tags=/gomla_wholesale_pos \
  --stop-after-init
```

لتحديث الموديول بعد تعديل الكود:

```bash
./odoo-bin -d your_database \
  --addons-path=addons,custom_addons \
  -u gomla_wholesale_pos \
  --stop-after-init
```

## حدود هذا الإصدار

- رصيد المورد الحالي هو Sub-ledger خاص بالموديول، ولا ينشئ `account.move` في المحاسبة العامة بعد.
- عهدة البرانيك الكاملة (خروج، رجوع، تالف، رد نقدي) ليست ضمن هذا الـVertical Slice؛ المنفذ الآن تحصيل الرهن وإظهار بياناته في البيع.
- إيصال Odoo القياسي مستخدم حاليًا مع تفاصيل الشحنة على السطور. مركز المطبوعات، سجل إعادة الطباعة وقوالب A4 مرحلة لاحقة.
- لا توجد مزامنة Cloud متعددة المحلات في هذا الإصدار؛ تشغيل Odoo نفسه متصل بالخادم، مع استمرار POS القياسي مؤقتًا عند انقطاع الاتصال.
- قبل الإنتاج يجب إجراء UAT على قاعدة منسوخة، وضبط الضرائب والحسابات وطرق الدفع وسياسة المرتجعات.

## الملفات المهمة للمبرمج

- `models/gomla_shipment.py`: دورة الشحنة والتصفية وسجل المورد.
- `models/pos_order.py`: حقول سطر البيع، التحقق الذري والربط بالمخزون.
- `models/pos_config.py`: إعدادات الـPOS وتحميل نماذج الشحنات.
- `static/src/app/control_buttons/`: امتداد واجهة Odoo 19 وإدخال بيانات البيع.
- `static/src/app/orderline/`: إظهار بيانات الشحنة داخل السطر والإيصال.
- `tests/`: قواعد العمل الأساسية القابلة للاختبار.
